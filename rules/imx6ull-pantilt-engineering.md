# IMX6ULL 安防云台项目工程规则

本规则服从 `plan/plan_imx6ull_pantilit_final.md`。当前目标是先完成安全、可观察的两自由度目标跟踪闭环，再做 IIO、ALSA、系统集成和性能优化。

## 1. 平台和职责边界

- IMX6ULL：OV5640 采集、PCA9685/MG90S 控制、传感器与 WM8960、设备接口和保护。
- PC：第一版目标定位、误差计算、P 控制决策和主要可视化。
- 第一版不得把 RKNN、NPU、RGA、RK3588 专用库或板端深度学习作为依赖。
- 平台不同的参考项目只能复用算法、协议和安全设计，不能直接照搬 Raspberry Pi/Arduino 的相机、GPIO 或 I2C 初始化代码。

## 2. 云台安全高于跟踪效果

- MG90S 上电前确认独立舵机供电、逻辑电源和共地；先测电压，再接舵机。
- 首次动作只允许从当前安全姿态小步移动，不得直接发送参考项目中的 0°、90°、180°或270°。
- 必须实测并持久化 `pan_min/center/max`、`tilt_min/home/max` 和方向；正式命令统一经过软件 clamp。
- 单次步长、更新频率和目标命令必须限幅；停止、退出、网络异常和严重 I2C 错误进入 HOLD 或 STOP，不继续累积动作。
- 首次试动已观察到突然的大幅运动。正式控制必须从已知的当前脉宽/姿态起步，按固定时间步进逐步靠近目标，并限制速度及加速度；禁止启动时直接跳到 1.5 ms 或某个固定“中心”值。转动速度与步长需在实物上由小到大标定。
- 机械标定未完成时，不得进入自动跟踪。

## 3. 最小跟踪闭环

第一版固定采用：

```text
OV5640 → 有界 Ring Buffer → PC OpenCV HSV/最大轮廓
→ 目标中心误差 → deadband + P + 最大步长
→ 带 seq/timestamp 的命令 → IMX6ULL 限位 → PCA9685 → Pan/Tilt
```

- 目标提取封装为 `get_target_center(frame)`，控制链不依赖具体检测算法。
- 目标丢失第一版进入 `LOST → HOLD`，自动搜索属于后续增强。
- 在 HSV+P 主闭环验收前，不引入 PID、YOLO、复杂 LCD UI、音频降噪或大规模性能调优。

## 4. 视频和控制时效

- 视频必须使用固定长度 Ring Buffer，建议 4～8 槽；禁止单槽 Latest Frame 取代计划中的 Ring Buffer。
- 缓冲满时覆盖或丢弃最旧帧，并记录读写索引、深度、高水位和 drop/overwrite 计数。
- 控制消息至少携带 `seq`、`timestamp`、模式及双轴控制量；重复、明显过期或非法命令必须拒绝并记录。
- 网络、显示、录像、音频或调试链路不得反向阻塞采集与云台安全控制。

## 5. 接口和迁移

- 先用 `/dev/i2c-X` 完成 `pantilt_test` 和标定，再建立 `/dev/pantilt0` 正式接口；不得为展示效果跳过底层验证。
- AP3216C/ICM20608 向 IIO 迁移时保留已验证字符设备路径，完成 A/B 数据核对后再决定退役旧实现。
- WM8960 阶段只补用户态 ALSA 录放音和错误恢复，不重新开发 Codec 驱动。
- 已验证旧链路不得提前删除；替代路径稳定且具备回退证据后再清理。

## 6. 可观察性和验证

至少观察：

- 云台命令、当前位置/脉宽、限位次数、I2C 错误、更新延迟；
- 视频 FPS、Ring Buffer 深度/高水位、丢帧/覆盖数；
- 目标中心、`error_x/error_y`、TRACK/LOST/HOLD 状态；
- 传感器丢包、ALSA XRUN、CPU 和内存（进入相应阶段时）。

每个 Phase 先通过最小功能验收，再增加抽象或优化。硬件链路只有在 IMX6ULL、实际 PCA9685、双 MG90S 和实测限位下运行后才可标记 `VERIFIED`；仅 PC 仿真或静态检查必须标记 `UNVERIFIED ON TARGET`。

## 7. 开源采用

优先级：官方文档/驱动 > `reference/pantilt_tracking.md` 中许可证明确且高度匹配的项目 > 仓库既有示例 > 最小自研。

采用上游实现时记录仓库链接、许可证、版本或提交、复用文件/算法、本地适配和验证结果。参考项目中的角度、PWM、增益、方向和性能数据均不得直接当作本机参数或成绩。

## 8. 板端连接与失联恢复

- 板端连接参数（开发机网卡地址、板端 IP、SSH 别名、主机密钥、部署目录）以 `connect/imx6ull_connection.md` 为准；不允许凭记忆或猜测改动 IP、用户名、密钥和 SSH 选项。
- 出现板端失联（SSH 超时、无法建连、认证失败）时，先查 `connect/imx6ull_connection.md`，按其"板端死机或重启时的检查顺序"逐项探测并恢复连接，不直接更换连接方式。
- 恢复动作限于只读探测与重连。未定位原因前不得反复自动重启板端，也不得把旧会话或旧日志当作本次结果。
- 摄像头相关的偶发故障按既有统一策略处理：有序归还模块退出，再重载重试。
